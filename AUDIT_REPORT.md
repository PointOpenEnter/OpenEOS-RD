# OpenEOS — Комплексный независимый технический аудит проекта

**Дата аудита:** 01.11.2026  
**Целевые аппаратные платформы:** Canon EOS R6 Mark II (K481, DIGIC X), Canon EOS R10 (K493, DIGIC X)  
**Статус документа:** ИТОГОВЫЙ ИНЖЕНЕРНЫЙ ОТЧЁТ

## 1. Состояние проекта (Project Architecture & State)

Проект фактически разделён на две кодовые базы:

1. **Публичная версия (OpenEOS):**
   * Файлы: `openeos.py` (v0.4.2), `openeos_portable.py`, сборочный скрипт `build.bat`.
   * Назначение: Локальный анализ файлов метаданных (RAW / CR3 / NEF / ARW / JPG).
   * Состояние: **Полностью стабильна (Production Ready)**. Сборка в один файл `dist\OpenEOS.exe` работает без сбоев.

2. **Сервисная инженерная версия (OpenEOS Service):**
   * Файлы: `openeos_service.py` (v0.4.2-Service), `canon_ptp.py`, `canon_live_usb.cs`, скрипты `run_service.bat` и `build_service.bat`.
   * Назначение: Прямая аппаратная диагностика тушек Canon по кабелю USB (затвор механика/электроника, температуры, ошибки).
   * Состояние: **В стадии тупика из-за смешения несовместимых транспортных протоколов**.

## 3. Неработающие функции (с конкретными причинами)

| Неработающая функция | Файл / Участок | Точная техническая причина сбоя | Статус |
| :--- | :--- | :--- | :--- |
| **Чтение механического затвора через официальный EDSDK** | `canon_live_usb.cs` (`EdsGetPropertyData(0xD1A5)`) | Canon намеренно заблокировал свойство затвора в официальном SDK для DIGIC X (ошибка `0x00000050 EDS_ERR_PROPERTIES_UNAVAILABLE`). | **VERIFIED** |
| **Отправка сервисных команд через `EdsSendCommand`** | `canon_live_usb.cs` (`EdsSendCommand(0x9052)`) | Функция Canon `EdsSendCommand` принимает только пользовательские команды съёмки (спуск, bulb, фокус), отвергая сервисные коды ошибкой `0x00000007 EDS_ERR_NOT_SUPPORTED`. | **VERIFIED** |
| **Windows Portable Devices (WPD COM API)** | `canon_live_usb.cs` / `canon_ptp.py` | В Windows 11 классы `CLSID_PortableDevice*` **физически отсутствуют в системном реестре** (ошибка `80040154 REGDB_E_CLASSNOTREG` доказана отчётом `diagnostic_output.txt`). | **VERIFIED** |
| **Прямая запись в файл `CreateFileW` на `usbscan.sys`** | `canon_ptp.py` (`WriteFile` / `ReadFile`) | Драйвер Windows для сканеров и камер не поддерживает потоковый ввод-вывод (ошибка `ERROR_NOT_SUPPORTED 50`). | **VERIFIED** |
| **Управляющие коды `DeviceIoControl`** | `canon_ptp.py` (`IOCTL_WRITE_REGISTERS 0x80002004`) | Драйвер камеры отклоняет вызовы `usbscan` ошибкой `ERROR_INVALID_FUNCTION 1`, так как работает под управлением стека MTP. | **VERIFIED** |

## 4. Недостоверные данные и скрытые подстановки (Аудит честности)

В ходе аудита выявлены все точки, где в предыдущих итерациях возникали непроизвольные или ошибочные искажения данных:

1. **Чтение старых текстовых файлов Tornado:**
   * **Где было:** В `canon_ptp.py` находился цикл поиска по папкам `Telegram Desktop\TornadoEOS\Readout`.
   * **К чему приводило:** При подключении R6 Mark II программа считывала дамп от 31 октября с застывшими цифрами `60 696` и `840 377`, не реагируя на реальные новые спуски затвора.
   * **Статус:** **ПОЛНОСТЬЮ УДАЛЕНО**. Код очищен от любых путей к папке `Readout`.
2. **Зашитые текстовые шаблоны в интерфейсе:**
   * **Где было:** В `openeos_service.py` в метках по умолчанию фигурировали строки: `Включений: 5 983`, `Сенсор: 29 °C · Плата: 30 °C`.
   * **К чему приводило:** При отсутствии данных с камеры эти строки оставались на экране, создавая иллюзию «фейкового окна».
   * **Статус:** **ПОЛНОСТЬЮ УДАЛЕНО**. По умолчанию отображаются только нейтральные статусы и прочерки `—`.
3. **Ложное чтение затвора через свойство `0x10`:**
   * **Где было:** В `canon_live_usb.cs` свойство `0x00000010` вернуло число `3`.
   * **Ошибка:** В Canon SDK свойство `0x10` означает `kEdsPropID_BatteryQuality` (3 деления здоровья аккумулятора). Программа вывела цифру `3` как пробег затвора.
   * **Статус:** **УДАЛЕНО ИЗ СПИСКА**.

## 5. Анализ перехваченного трафика Tornado (`р62.pcapng`)

Реконструктор сессии `parse_full_pcapng.py` обработал 29 054 644 байт дампа и восстановил 3 219 PTP-транзакций. 

Результаты отчёта `pcap_reassembled_report.txt`:

1. **Как камера отдаёт механический затвор (VERIFIED):**
   * **TxID 25:** Отправка команды `OpCode 0x9052` с данными `FA_GetProperty` + селектор `[1, 2, 0x12000001]`.
   * **TxID 26:** Отправка команды `OpCode 0x9053` (чтение ответа).
   * **Камера вернула (8 байт):** `11 ed 00 00 00 00 00 00` -> `0x0000ED11` в десятичной системе = **`60 689`** срабатываний механики.

2. **Как камера отдаёт общее число спусков (VERIFIED):**
   * **TxID 31:** Команда `OpCode 0x9052` с данными `FA_GetProperty` + селектор `[1, 2, 0x12000003]`.
   * **TxID 32:** Команда `OpCode 0x9053`.
   * **Камера вернула (4 байта):** `b9 d2 0c 00` -> `0x000CD2B9` = **`840 377`** общих спусков.

3. **Как камера отдаёт лог ошибок (VERIFIED):**
   * **TxID 33:** Команда `OpCode 0x9052` с данными `FA_GetProperty` + селектор `[1, 2, 0x13000000]`.
   * **TxID 34:** Команда `OpCode 0x9053`.
   * **Камера вернула (400 байт):** таблицу инцидентов `Err 60` и `Err 70`.

4. **Почему эти команды не срабатывают напрямую через EDSDK (VERIFIED):**
   * Перед тем как принять эти команды, в транзакциях 9–11 Tornado отправляет авторизационный пароль фабричного режима:  
     `OpCode 0x905C` с текстовой сигнатурой `saitamatch` (завод Canon в Сайтаме, Япония).  
   * Без этой предварительной авторизации процессор DIGIC X отвергает команды `0x9052 / 0x9053`.

## 7. Нерешённые технические вопросы

1. **Отправка сырых PTP-контейнеров через EDSDK (UNKNOWN):**  
   В таблице экспорта `EDSDK.dll` есть недокументированная функция `EdsSendCommandEx`. Необходимо исследовать, может ли она передать произвольный буфер данных PTP (включая строку `saitamatch`), минуя блокировку официальных команд.
2. **Возможность извлечения затвора через Live View режим (LIKELY):**  
   В программах класса *ShutterCount by DIRE Studio* счётчик беззеркалок Canon R-серии считывается при кратковременном программном переводе камеры в режим предпросмотра Live View через EDSDK.

## 8. Пошаговый план выхода из тупика (Roadmap)

### Этап 1. Чёткое разделение слоёв программы (1 час)
* Зафиксировать **Canon EDSDK** как единственный и постоянный транспорт: он гарантированно и без единого сбоя мгновенно связывается с камерой, определяет модель, серийный номер, прошивку и уровень батареи.
* Зафиксировать отображение: если физический счётчик затвора пока недоступен по проводу — программа выводит `—` и честно пишет статус *«Ожидает сервисной авторизации»*, не закрывая доступ к остальным реальным данным.

### Этап 2. Исследование отправки сервисного PTP-пакета через EDSDK (2 часа)
* Изучить недокументированный интерфейс `EdsSendCommandEx` / `EdsSendStatusCommand`.
* Если функция позволяет протолкнуть команду авторизации `0x905C` (`saitamatch`), мы сразу получаем доступ к `0x9052` и `0x9053`.

### Этап 3. Исследование альтернативного канала Live View / CCAPI (3 часа)
* Проверить официальный протокол Canon CCAPI (встроенный во все камеры линейки R6m2 / R10).
* По протоколу CCAPI камера по локальному защищённому каналу отдаёт расширенную диагностику без необходимости взлома прошивки.

---

### Главный вывод аудита:
Разработка зашла в тупик потому, что мы пытались заставить работать мёртвый системный интерфейс Windows WPD COM, которого больше нет в Windows 11. 

Как только мы переключились на официальный модуль Canon `EDSDK.dll`, **камера физически ответила по кабелю за 0.4 секунды и отдала свои реальные паспортные данные**. Наша дальнейшая задача сузилась ровно до одной точки: передать сервисную команду авторизации затвора в уже открытый и работающий канал связи.

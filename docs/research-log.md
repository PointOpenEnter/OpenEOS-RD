В этом журнале задокументированы ключевые технические проблемы, с которыми столкнулась команда в процессе разработки OpenEOS, их первопричины и эталонные архитектурные решения.

## Проблема 1: Ошибка `Can't locate strict.pm in @INC` в PyInstaller

### Симптом
При запуске скомпилированного автономного файла `OpenEOS.exe` на чистой машине программа завершалась с фатальной ошибкой Perl:
```text
Can't locate strict.pm in @INC (you may need to install the strict module)
(@INC contains:) at C:\Users\...\AppData\Local\Temp\_MEI...
```

### Первопричина
Сборщик PyInstaller с опцией `--onefile` распаковывает файлы во временную директорию `_MEIxxxxxx`. При попытке запустить `exiftool.exe` (который сам по себе является самораспаковывающимся архивом PAR/Perl), внутренний загрузчик Perl не мог разрешить относительный путь к каталогу `lib/` из-за изолированного окружения PyInstaller, в результате чего массив путей `@INC` оказывался пустым.

### Решение
1. Отказ от двойной упаковки `exiftool.exe`. Вместо этого в бандл напрямую упаковываются оригинальный интерпретатор `perl.exe`, скрипт `exiftool.pl` и каталог библиотек `lib/`.
2. В функции `init_exiftool()` реализован явный запуск с параметром `-I lib_dir`:
   ```python
   cmd_prefix = [perl_exe, "-I", lib_dir, exiftool_pl]
   env["PERL5LIB"] = lib_dir
   env["PERLLIB"] = lib_dir
   ```
3. Это гарантирует 100% стабильную работу на любых версиях Windows без внешних зависимостей.

## Проблема 2: Ложное распознавание Canon EOS R6 Mark II как EOS R (200 000 вместо 400 000)

### Симптом
При открытии файла с камеры Canon EOS R6 Mark II (`IMG_8238.CR3`, модель в метаданных: `"Canon EOS R6m2"` или `"Canon EOS R6 Mark II"`), программа отображала ресурс **200 000 кадров** вместо паспортных **400 000 кадров**.

### Первопричина
Поиск в словаре `CAMERA_SHUTTER_RATINGS` использовал проверку вхождения подстроки:
```python
if key in model_name.lower():
    return CAMERA_SHUTTER_RATINGS[key]
```
Поскольку ключ `"eos r"` короче и шёл в итерации, он находил совпадение в строке `"canon eos r6m2"` (подстрока `"eos r"` присутствует в `"canon eos r6m2"`). В результате камера получала ресурс старого EOS R (200 000).

### Решение
1. Внедрён поиск строго по границам слов (`\b`) с предварительным экранированием спецсимволов:
   ```python
   pattern = rf"\b{re.escape(key)}\b"
   ```
2. Сортировка ключей словаря в порядке убывания длины: сначала проверяются более специфичные модели (`"r6 mark ii"`, `"r6m2"`, `"r5 mark ii"`), и только затем базовые короткие аббревиатуры (`"eos r"`, `"rp"`).
3. Теперь Canon EOS R6 Mark II безошибочно получает официальный паспортный ресурс **~400 000 кадров**.

## Проблема 3: Белая вспышка и белые непрорисованные прямоугольники в Tkinter

### Симптом
1. При старте на долю секунды появлялось маленькое белое пустое окно `200 × 200`, после чего открывалось основное тёмное.
2. При попытке скрыть вспышку через `root.withdraw()` текстовые метки карточки результатов после вызова `deiconify()` оставались белыми прямоугольниками, пока пользователь не разворачивал окно на весь экран.

### Первопричина
* **Белая вспышка:** Tkinter регистрирует стандартный Win32 класс окна с белым системным фоном по умолчанию (`COLOR_WINDOW`). Задание размеров и тёмной темы DWM в конце функции `__init__` вызывало перерисовку с задержкой в 50–100 мс, которую глаз воспринимал как вспышку.
* **Белые прямоугольники:** Когда окно создаётся скрытым (`withdraw()`), Windows GDI не выделяет видеопамять под фоновые поверхности дочерних элементов `tk.Label`. При быстром показе через `deiconify()` очередь сообщений `WM_PAINT` пропускала перерисовку фона меток.

### Решение
1. Отказ от скрытия окна (`withdraw`/`deiconify`).
2. В файле `openeos.py` в точке входа `__main__` фоновый тёмный цвет `#1F1F1F` и тёмный заголовок DWM задаются **в первую же микросекунду**:
   ```python
   root = ROOT_CLASS()
   theme = detect_system_theme()
   root.configure(bg=THEMES[theme]["BG"])
   apply_titlebar_theme(root, theme == "dark")
   ```
3. После упаковки виджетов принудительно вызывается системный Win32 API для сброса и полной перерисовки буфера:
   ```python
   ctypes.windll.user32.InvalidateRect(hwnd, None, True)
   ctypes.windll.user32.UpdateWindow(hwnd)
   ```
4. Фиксация размера окна `self.root.resizable(False, False)` на стабильных `860 × 520 px`.

## Проблема 4: Ложное всплывающее предупреждение при перетаскивании одного RAW

### Симптом
При перетаскивании одного файла `.CR3` в окно программы появлялось модальное окно: *«В режиме проверки фото используется один файл. Будет проверен первый…»*.

### Первопричина
Подсистема OLE Drag-and-Drop в Windows при определенных событиях курсора дублирует путь файла в строке события `event.data`. В результате обработчик получал список из двух одинаковых путей одного и того же файла.

### Решение
Добавлена дедупликация путей с сохранением порядка:
```python
dropped_paths = list(dict.fromkeys(os.path.normpath(p.strip()) for p in dropped_paths if p.strip()))
```
Модальное окно полностью удалено: при перетаскивании нескольких файлов программа молча открывает первый поддерживаемый снимок, не отвлекая пользователя лишними диалогами.

# SCIENTIFIC AUDIT CONCLUSION & FORENSIC TAXONOMY
**Investigation:** Forensic Audit of Canon EOS R6 Mark II Service Capture (`р62.pcapng`)  
**Investigator:** OpenEOS Independent Engineering Review  
**Date:** November 2026  
**Primary Question:** Did Tornado retrieve the mechanical shutter count and total releases directly from the camera via USB PTP, how was it done, and is it non-destructive?

---

## 1. Classification Methodology

To ensure strict scientific and forensic integrity, every finding from this investigation is categorized under four distinct evidential standards:
* **[VERIFIED]:** Directly proven by raw byte sequences, packet headers, USB transfer descriptors, and mathematically undeniable decoded values from `р62.pcapng`.
* **[LIKELY]:** High-confidence deduction based on known Canon DIGIC system architecture, libgphoto2 research, and standard camera engineering, but lacking official Canon proprietary documentation.
* **[UNKNOWN]:** Information that cannot be resolved solely from USB packet sniffing without internal Canon firmware disassembly or hardware debugging.
* **[REFUTED / SPECULATION]:** Past claims, hypotheses, or community assumptions that have been disproven or lack forensic grounding.

## 2. Taxonomy of Findings

### A. [VERIFIED] Facts (100% Empirically Proven)

1. **Camera Authenticity & Model:**
   * VID: `0x04A9` (Canon Inc.), PID: `0x330B` (Canon EOS R6 Mark II).
   * Serial Number: `183121000830` (read from DeviceInfo dataset).
   * Firmware Version: `1.7.0` (DryOS / DIGIC X platform).
2. **Mechanical Shutter Actuation Count = 60,689:**
   * Retrieved in **TxID 25 & 26**.
   * In TxID 25, the host calls `FA_GetProperty` with Key `0x12000001`.
   * In TxID 26, the camera returns **Bulk IN (Device-to-Host)** payload `11 ed 00 00 00 00 00 00`.
   * Little-Endian `0x0000ED11` = **`60 689`**.
3. **Total Releases Count = 840,377:**
   * Retrieved in **TxID 31 & 32**.
   * In TxID 31, the host calls `FA_GetProperty` with Key `0x12000003`.
   * In TxID 32, the camera returns **Bulk IN (Device-to-Host)** payload `b9 d2 0c 00`.
   * Little-Endian `0x000CD2B9` = **`840 377`**.
4. **Diagnostic Incident Error Log:**
   * Retrieved in **TxID 33 & 34** via Key `0x13000000`.
   * Returns a 400-byte structured binary log detailing historical error events (`Err 60` diaphragm communication error and `Err 70` image buffer anomaly).
5. **USB Direction of Returned Data:**
   * The counter payloads are carried on **Bulk Endpoint `0x81`** (Endpoint 1, Direction IN).
   * The USBPcap event flag is `0x01` (device-to-host), under completed read IRP `0xFFFF800100A11A00`.
   * **Conclusion:** The values 60,689 and 840,377 were generated by the camera's internal microcontroller and transmitted to the PC. They were not injected by Tornado.
6. **PTP Command Container Length:**
   * PTP command containers with 2 parameters (such as `0x9052` in TxID 25) have an exact length of **20 bytes (`0x14`)**.
   * The previous report's text mentioning `0x0C` was an erroneous copy-paste string in prose; the captured binary is 100% compliant with ISO 15740.
7. **USBPcap Header Offsets in Analysis Tools:**
   * Fixed critical offset errors in legacy `dump_seq.py`:
     * Endpoint is at byte offset **21** (`pkt_data[21]`), not offset 22.
     * Transfer Type is at byte offset **22** (`pkt_data[22]`), not offset 23.
     * USB Data starts at offset `header_len` (typically 27 or 28 bytes).
8. **Absence of Non-Volatile Memory (EEPROM) Writes:**
   * Throughout all 24,379 packets, there is **zero (0) execution** of EEPROM or flash programming commands (`FA_WriteEepromData`, `WriteMemory`, etc.).
   * The session is completely read-only and safe with respect to persistent storage.

### B. [LIKELY] Deductions (High Probability)

1. **Total Releases Semantics:**
   * Property `0x12000003` reflects the total release triggers across all capture modes (mechanical, electronic front curtain, and full electronic shutter).
2. **Data Type Descriptor:**
   * The second uint32 field (`02 00 00 00`) in the `FA_GetProperty` request represents scalar integer property format (Type 2 = 32-bit uint).
3. **Volatile Session Lifetime:**
   * Because the factory unlock bits are held in volatile RAM, all service states revert automatically to normal user mode when the camera is powered off or disconnected from USB.

1. **Detailed Electronic Actuation Weighting:**

2. **Cryptographic Algorithm of Handshake:**
   * The exact mathematical transformation connecting the challenge nonce in `saitamatch` to the returned authorization token in `gunmafukaya` requires disassembly of the DryOS service task (`FA_Task`).

### D. [REFUTED / SPECULATION] Past Claims Disproven

1. **"Tornado executed 7 EEPROM write operations":**
   * **REFUTED.** The seven outgoing transfers were authentication tokens (`saitamatch`, `gunmafukaya`) and volatile session configurations (`FA_TurnOffDisplay`, `cc_cmd_playbtn_on`, `DisablePowerSave`). None wrote to persistent memory.
2. **"Difference 840,377 - 60,689 is strictly the Electronic Shutter count":**
   * **SPECULATION / UNVERIFIED.** While widely assumed by user utilities, calling this "pure electronic shutter" is technically inaccurate without knowing whether sensor calibration and video triggers are included. It must be scientifically labeled as **Total Releases minus Mechanical Actuations**.
3. **"Session used `InitializeAdjustmentSystem`, `blefa_startfactory`, or `blefa_endfactory`":**
   * **REFUTED.** Not a single occurrence of these legacy DSLR/Bluetooth strings exists in `р62.pcapng`.
4. **"Key `0x12000001` is MPU Memory Address `0x1001`":**
   * **REFUTED.** DIGIC X does not support legacy MPU monitor commands (`0x9005–0x9008`). Key `0x12000001` is a logical 32-bit property identifier within the `FA_GetProperty` service subsystem.
